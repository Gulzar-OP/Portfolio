0. Sliding Window kya hota hai?

Jab hume kisi array/string ke contiguous part (subarray/substring) pe kaam karna ho (sum, max, min, distinct count etc), aur brute force O(n²) lag raha ho — Sliding Window use karte hain to make it O(n).

Idea: ek "window" (range) leke usko array pe slide karte hain — har baar poora dobara calculate karne ke bajaye, sirf edges update karte hain (ek element add, ek remove).

l  .....  r ↓ window = arr[l...r] r++ → naya element ANDAR ↓ (agar condition toot jaye) l++ → purana element BAHAR

Types (is notes me cover honge):

  • 1. Fixed Size Window — window size k FIXED rehta hai
  • 2. Variable Size Window — condition ke hisaab se grow/shrink hota hai
  • 3. Window + HashMap/Freq array — chars/distinct count track karne ke liye
  • 4. Window Maximum/Minimum — Monotonic Deque use hota hai
  • 5. Minimum Window Substring type — variable + hashmap combo (hardest)

1. Fixed Size Sliding Window

Kab use karna: Jab problem me window size k already diya ho — jaise "max sum of subarray of size k".

Example: arr = [2, 1, 5, 1, 3, 2], k = 3  →  Max sum subarray of size 3 nikalo.
int maxSumK(vector<int>& arr, int k) { int n = arr.size(); int windowSum = 0, maxSum = 0; // pehla window banao for (int i = 0; i < k; i++) windowSum += arr[i]; maxSum = windowSum; // ab slide karo: ek naya add, ek purana remove for (int i = k; i < n; i++) { windowSum += arr[i] - arr[i - k]; maxSum = max(maxSum, windowSum); } return maxSum; }

Trick: windowSum += arr[i] - arr[i-k] → yehi pura sliding window ka magic hai (O(1) update, dobara sum nahi karna)

Answer = 9 (window [5,1,3])

Time: O(n) | Space: O(1)

2. Variable Size Sliding Window

Kab use karna: Jab window ka size FIXED nahi hai — condition ke basis pe grow (r++) ya shrink (l++) karna padta hai.

Example: arr = [2,1,5,2,3,2], target = 7  →  Smallest subarray jiska sum ≥ target ho.
int smallestSubWithSum(vector<int>& arr, int target) { int n = arr.size(); int l = 0, sum = 0, minLen = INT_MAX; for (int r = 0; r < n; r++) { sum += arr[r]; // window GROW karo while (sum >= target) { // condition satisfy → SHRINK karo minLen = min(minLen, r - l + 1); sum -= arr[l]; l++; } } return (minLen == INT_MAX) ? 0 : minLen; }

Pattern yaad rakho: for(r) se grow, andar while(condition) se shrink — yeh template 80% variable window problems me chalta hai!

3. Window + HashMap (distinct chars)

Kab use karna: String problems jaha character frequency / distinct count track karna ho.

Example: s = "abcabcbb"  →  Longest substring without repeating characters
int lengthOfLongestSubstring(string s) { unordered_map<char,int> freq; int l = 0, maxLen = 0; for (int r = 0; r < s.size(); r++) { freq[s[r]]++; // agar duplicate ban gaya, shrink from left while (freq[s[r]] > 1) { freq[s[l]]--; l++; } maxLen = max(maxLen, r - l + 1); } return maxLen; }

4. Sliding Window Maximum (Monotonic Deque)

Kab use karna: Har window ka max/min chahiye, fast (O(n)) — normal loop se O(n·k) lagta, isliye deque use karte hain.

Example: arr = [1,3,-1,-3,5,3,6,7], k = 3  →  Har window ka max nikalo.
vector<int> maxSlidingWindow(vector<int>& arr, int k) { deque<int> dq; // stores INDEX, values decreasing order vector<int> result; for (int i = 0; i < arr.size(); i++) { // 1) front expire ho gaya to nikaal do if (!dq.empty() && dq.front() <= i - k) dq.pop_front(); // 2) back se chhote elements nikaal do (unka koi use nahi) while (!dq.empty() && arr[dq.back()] < arr[i]) dq.pop_back(); dq.push_back(i); // 3) window complete hote hi front hi answer hai if (i >= k - 1) result.push_back(arr[dq.front()]); } return result; }

Deque hamesha decreasing order me rehta hai (front = current max). Har element ek baar push, ek baar pop → O(n) amortized.

Dry Run (k=3): arr = [1,3,-1,-3,5,3,6,7]

5. Minimum Window Substring (hardest type)

Kab use karna: Variable window + HashMap dono combine — "smallest window jisme kuch specific chars/counts sab present ho".

Example: s = "ADOBECODEBANC", t = "ABC"  →  Smallest substring of s jisme A,B,C sab present ho.
string minWindow(string s, string t) { unordered_map<char,int> need, window; for (char c : t) need[c]++; int l = 0, have = 0, needCnt = need.size(); int bestLen = INT_MAX, bestStart = 0; for (int r = 0; r < s.size(); r++) { char c = s[r]; window[c]++; if (need.count(c) && window[c] == need[c]) have++; // condition satisfy → shrink karke best nikaalo while (have == needCnt) { if (r - l + 1 < bestLen) { bestLen = r - l + 1; bestStart = l; } char lc = s[l]; window[lc]--; if (need.count(lc) && window[lc] < need[lc]) have--; l++; } } return bestLen == INT_MAX ? "" : s.substr(bestStart, bestLen); }

"have == needCnt" ka matlab: t ke saare distinct chars ki required count window me pooch chuki hai → ab shrink karo, jab tak condition tootey nahi.

Answer = "BANC"

6. General Template (yaad rakhne ke liye)

Fixed Size Window:

for(i=0;i<k;i++) build window; for(i=k;i<n;i++){ add arr[i]; remove arr[i-k]; update answer; }

Variable Size Window:

l=0; for(r=0;r<n;r++){ add arr[r]; while(condition breaks){ remove arr[l]; l++; } update answer; }

8. Common Mistakes (dhyan rakhna!)

  • ✗ Fixed window me har baar poora sum recalculate karna — ✓ sirf +new -old karo
  • ✗ Variable window me while ki jagah if laga dena — shrink ek baar me poora nahi hoga
  • ✗ HashMap me count 0 hone ke baad bhi key delete na karna (distinct count galat aayega)
  • ✗ Deque me sirf value store karna, index nahi — expiry check nahi ho payega
  • ✓ Hamesha socho: "l aur r kab move karenge?" pehle likho, phir code karo

9. Kaise Pehchane — Sliding Window use karna hai ya nahi?

Problem me "subarray/substring" + contiguous? ↓ YES Kuch cheez (sum/count/max) minimize/maximize karni hai? ↓ YES 🎯 SLIDING WINDOW try karo!

Agar "subsequence" (non-contiguous) ho → sliding window kaam NAHI karega, wo DP/other approach hai.
